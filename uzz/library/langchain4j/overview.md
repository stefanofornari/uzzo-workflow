# LangChain4j — Overview & Core Concepts

> Reference article for integrating LangChain4j into Java projects.
> Source: https://docs.langchain4j.dev/

---

## What is LangChain4j?

LangChain4j is a Java library that supercharges Java applications with the power of LLMs (Large Language Models). It provides both **low-level** building blocks and **high-level abstractions** (AI Services) that hide the complexity of prompt management, memory, tool calling, and output parsing.

---

## Maven Dependency (core)

```xml
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j</artifactId>
    <version>1.0.0-beta3</version> <!-- check Maven Central for latest -->
</dependency>
```

Add a provider-specific integration module alongside the core (e.g., OpenAI, Ollama, Google Vertex AI, etc.):

```xml
<!-- Example: OpenAI -->
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-open-ai</artifactId>
    <version>1.0.0-beta3</version>
</dependency>
```

> Always verify the latest version on [Maven Central](https://central.sonatype.com/artifact/dev.langchain4j/langchain4j).

## Architecture: Low-level vs High-level API

| Layer | API | When to use |
|-------|-----|-------------|
| Low-level | `ChatModel`, `ChatMessage`, `ChatMemory` | Full control, custom orchestration |
| High-level | `AiServices` | Declarative, business-logic-focused code |

### Recommended approach for new projects: AI Services (high-level)

---

## Core Concepts

### 1. ChatModel (low-level)

The primary entry point for interacting with an LLM.

```java
// Simple string-in / string-out
String response = model.chat("Hello, what is your name?");

// Typed — returns ChatResponse with metadata (token usage, finish reason)
ChatResponse response = model.chat(UserMessage.from("Hello!"));
AiMessage aiMessage = response.aiMessage();
```

### 2. ChatMessage types

| Type | Description |
|------|-------------|
| `UserMessage` | Input from the user (or the application itself) |
| `AiMessage` | Response generated by the model |
| `SystemMessage` | Instructions/persona set by the developer (placed first) |
| `ToolExecutionResultMessage` | Result of a tool/function call |
| `CustomMessage` | Provider-specific (currently Ollama only) |

`AiMessage` can contain: `text()`, `thinking()` (reasoning models), `toolExecutionRequests()`.

### 3. ChatMemory

LLMs are stateless. `ChatMemory` manages conversation history across turns.

| Implementation | Behaviour |
|----------------|-----------|
| `MessageWindowChatMemory` | Sliding window — keeps the last N messages |
| `TokenWindowChatMemory` | Evicts oldest messages when token budget is exceeded |

```java
ChatMemory memory = MessageWindowChatMemory.withMaxMessages(20);
```

### 4. AI Services (high-level — recommended)

Declare an interface and let LangChain4j provide the implementation via a dynamic proxy — similar to Spring Data JPA.

```java
// 1. Declare the interface
interface ScopeAgent {
    String chat(String userMessage);
}

// 2. Build the service
ScopeAgent agent = AiServices.builder(ScopeAgent.class)
    .chatLanguageModel(model)
    .chatMemory(MessageWindowChatMemory.withMaxMessages(20))
    .build();

// 3. Use it
String reply = agent.chat("I want to build a scope agent for Viber.");
```

AI Services automatically handle:
- Prompt formatting (`@SystemMessage`, `@UserMessage` annotations)
- Chat memory management
- Tool execution (via `@Tool`)
- Output parsing (return types: `String`, POJOs, enums, etc.)

### 5. Tools (Function Calling)

Annotate any Java method with `@Tool` to let the LLM call it autonomously:

```java
public class MyTools {
    @Tool("Saves the scope document to the given file path")
    public void saveScopeDocument(String filePath, String content) {
        // write to disk
    }
}

ScopeAgent agent = AiServices.builder(ScopeAgent.class)
    .chatLanguageModel(model)
    .chatMemory(memory)
    .tools(new MyTools())
    .build();
```

The model decides when and how to invoke tools based on the conversation.
