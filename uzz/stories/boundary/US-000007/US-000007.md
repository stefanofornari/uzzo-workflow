## boundary/US-000007 — Partition Discussed Items into In-Scope Capabilities

### User Story

```
AS A Developer
I WANT the Scope Agent to classify all discussed items into an explicit In-Scope Capabilities list
SO THAT the final scope document clearly states what the project will deliver
```

#### Technical Context & Constraints
* **Target System**: ViberFX desktop application / ViberCLI terminal interface
* **Toolchain / Rules**: Java, JavaFX, Maven; Viber `Viber`-`Actor` framework; coding standard `uzz/specs/coding_standard.md`; development framework `uzz/specs/development_framework.md`

#### Notes
1. "Discussed items" includes everything surfaced during the prompt analysis and clarification dialogue.
2. An item is In-Scope only if it has been explicitly confirmed by the Developer during the dialogue.
3. The in-scope list is structured by functional domain, matching the domains identified in the analysis phase.

### Acceptance Criteria

```gherkin
Scenario: Items confirmed during clarification are placed in-scope
  Given the clarification phase is complete with N confirmed items
  When  the agent partitions items
  Then  all N confirmed items appear in the In-Scope Capabilities list
  And   no unconfirmed item appears in-scope

Scenario: Items are grouped by functional domain
  Given the In-Scope Capabilities list is being built
  When  the agent organizes it
  Then  each item is assigned to a named functional domain
  And   the list is grouped by domain

Scenario: Ambiguous item with no Developer confirmation
  Given an item that was discussed but never explicitly confirmed by the Developer
  When  the agent partitions items
  Then  the item is NOT placed in-scope
  And   it is held for out-of-scope evaluation
```
