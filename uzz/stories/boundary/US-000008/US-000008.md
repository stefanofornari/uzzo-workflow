## boundary/US-000008 — Enforce Scope Guarding and Build Out-of-Scope List

### User Story

```
AS A Developer
I WANT the Scope Agent to treat anything not explicitly listed in-scope as Out-of-Scope by default and build an explicit out-of-scope list
SO THAT the project boundaries are unambiguous and no hidden assumptions creep into the scope document
```

#### Technical Context & Constraints
* **Target System**: ViberFX desktop application / ViberCLI terminal interface
* **Toolchain / Rules**: Java, JavaFX, Maven; Viber `Viber`-`Actor` framework; coding standard `uzz/specs/coding_standard.md`; development framework `uzz/specs/development_framework.md`

#### Notes
1. Scope Guarding rule: any capability discussed but not confirmed in-scope defaults to out-of-scope.
2. Out-of-scope items must be recorded explicitly — they are not simply omitted from the document.
3. Future enhancement items surfaced during dialogue are also captured in the out-of-scope list.

### Acceptance Criteria

```gherkin
Scenario: Unconfirmed items default to out-of-scope
  Given a set of items discussed during the dialogue
  And   some items were not explicitly confirmed in-scope by the Developer
  When  scope guarding is applied
  Then  each unconfirmed item is placed in the Out-of-Scope list
  And   no unconfirmed item appears in the In-Scope Capabilities list

Scenario: Out-of-scope items are explicitly recorded
  Given a finalized boundary partition
  When  the out-of-scope list is built
  Then  each out-of-scope item is recorded with a brief label
  And   the list is non-empty when applicable

Scenario: Items explicitly stated as future enhancements are captured
  Given the Developer explicitly labels an item as a future enhancement during dialogue
  When  the agent processes the boundary
  Then  that item appears in the Out-of-Scope / Future Enhancements section
```
