## analysis/US-000003 — Identify Unresolved Requirements and Constraints

### User Story

```
AS A Developer
I WANT the Scope Agent to explicitly identify unresolved requirements, platform assumptions, and architectural constraints within my prompt
SO THAT these specifics can be targeted by clarifying questions and are not silently assumed
```

#### Technical Context & Constraints
* **Target System**: ViberFX desktop application / ViberCLI terminal interface
* **Toolchain / Rules**: Java, JavaFX, Maven; Viber `Viber`-`Actor` framework; coding standard `uzz/specs/coding_standard.md`; development framework `uzz/specs/development_framework.md`

#### Notes
1. This story refines the gap list from US-000002 by categorizing gaps into three types: unresolved requirements, platform assumptions, and architectural constraints.
2. No Speculation policy: the agent must never assume a value for any unknown — it must surface it for clarification.
3. Categorization is stored internally and is consumed by clarify/US-000004 to generate targeted questions.

### Acceptance Criteria

```gherkin
Scenario: Gaps are categorized correctly
  Given a gap list produced by the analysis step (US-000002)
  When  the agent categorizes the gaps
  Then  each gap is labeled as one of: "unresolved requirement", "platform assumption", or "architectural constraint"
  And   no gap remains uncategorized

Scenario: No Speculation policy is enforced
  Given a prompt that omits the target database technology
  When  the agent identifies this as a gap
  Then  the agent does NOT assume a default database technology
  And   the gap is added to the categorized list with label "architectural constraint"

Scenario: Empty gap list
  Given a gap list with zero entries
  When  the agent attempts categorization
  Then  the agent records that no categorization is needed
  And   proceeds without entering the clarification flow
```
