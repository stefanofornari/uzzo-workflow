## compile/US-000010 — Populate Core Scope Document Fields

### User Story

```
AS A Developer
I WANT the Scope Agent to populate Project Name, Version, Overall Description, In-Scope Capabilities, and Out-of-Scope sections using only information I provided
SO THAT the scope document accurately reflects my intent without any hallucinated or assumed content
```

#### Dependencies
- compile/US-000009

#### Technical Context & Constraints
* **Target System**: ViberFX desktop application / ViberCLI terminal interface
* **Toolchain / Rules**: Java, JavaFX, Maven; Viber `Viber`-`Actor` framework; coding standard `uzz/specs/coding_standard.md`; development framework `uzz/specs/development_framework.md`
* **No Speculation policy**: any unknown value must be asked from the Developer, never assumed.

#### Notes
1. Project Name, Version, and Overall Description come from what the Developer stated during the dialogue.
2. In-Scope Capabilities must be organized by domain with checkbox items.
3. Out-of-Scope / Future Enhancements section is populated from the boundary partition (US-000008).
4. If any mandatory field value is unknown at compilation time, the agent must ask the Developer rather than speculating.

### Acceptance Criteria

```gherkin
Scenario: All core fields are populated from Developer-provided information
  Given a completed clarification and boundary definition phase
  When  the agent populates the scope document
  Then  Project Name, Version, and Overall Description are filled with Developer-provided values
  And   no field contains a placeholder or assumed value

Scenario: In-Scope Capabilities are organized by domain with checkboxes
  Given the finalized in-scope list grouped by domain
  When  the agent populates the In-Scope Capabilities section
  Then  each domain appears as a named subsection
  And   each capability is rendered as a checkbox item (e.g., "- [ ] capability text")

Scenario: No Speculation policy — unknown field triggers a question
  Given the agent reaches compilation and the Version field was never provided
  When  the agent encounters the unknown value
  Then  the agent stops compilation and asks the Developer for the Version
  And   compilation resumes only after the Developer provides the value
```
