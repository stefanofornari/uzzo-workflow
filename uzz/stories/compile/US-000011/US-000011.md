## compile/US-000011 — Populate Technical Context and Infrastructure Section

### User Story

```
AS A Developer
I WANT the Scope Agent to populate the Technical Context & Infrastructure section of the scope document using only information I explicitly provided
SO THAT the technical context is accurate and auditable, with no guessed stacks, platforms, or paths
```

#### Status
TODO

#### Dependencies
- compile/US-000010

#### Technical Context & Constraints
* **Target System**: ViberFX desktop application / ViberCLI terminal interface
* **Toolchain / Rules**: Java, JavaFX, Maven; Viber `Viber`-`Actor` framework; coding standard `uzz/specs/coding_standard.md`; development framework `uzz/specs/development_framework.md`
* **No Speculation policy**: technical stacks, platforms, project reference paths, and any unknown value must be explicitly provided by the Developer.

#### Notes
1. Technical Context includes: development toolchain, target systems/platforms, skill/template sources, output format, and reference document paths.
2. If the Developer did not provide a value for a technical context item, the agent must ask before filling it.
3. Reference paths in the document must match actual paths confirmed by the Developer.

### Acceptance Criteria

```gherkin
Scenario: Technical Context section is populated from Developer-provided values
  Given the Developer provided toolchain and platform details during the dialogue
  When  the agent populates the Technical Context section
  Then  all technical values reflect exactly what the Developer stated
  And   no assumed or invented technical value appears

Scenario: Unknown technical stack triggers a question (No Speculation)
  Given the Developer never mentioned the development language
  When  the agent reaches the Technical Context section during compilation
  Then  the agent asks the Developer for the development language
  And   does not insert a default or guessed value

Scenario: Reference paths are only those confirmed by the Developer
  Given the Developer provided specific reference document paths during clarification
  When  the agent populates Reference Docs in Technical Context
  Then  only the Developer-confirmed paths appear
  And   no additional paths are fabricated
```
