## persist/US-000013 — Update an Existing Scope File In Place

### User Story

```
AS A Developer
I WANT the Scope Agent to update an existing scope file in place when the target file already exists
SO THAT I can refine the scope incrementally without losing the previous version or creating duplicate files
```

#### Technical Context & Constraints
* **Target System**: ViberFX desktop application / ViberCLI terminal interface
* **Toolchain / Rules**: Java, JavaFX, Maven; Viber `Viber`-`Actor` framework; coding standard `uzz/specs/coding_standard.md`; development framework `uzz/specs/development_framework.md`

#### Notes
1. An in-place update overwrites the entire content of the existing file with the new compiled scope document.
2. The agent must detect that the target file already exists before deciding to update rather than create.
3. No backup or version history is required by this story (multi-session versioning is explicitly out of scope).

### Acceptance Criteria

```gherkin
Scenario: Target file exists — agent updates it in place
  Given a compiled scope document and a target file path that already exists
  When  the agent persists the document
  Then  the existing file is overwritten with the new scope document content
  And   no duplicate file is created

Scenario: Agent detects existing file before writing
  Given a target file path provided by the Developer
  When  the agent checks for an existing file
  Then  if the file exists, the update path is taken
  And   if the file does not exist, the create path is taken (US-000012)

Scenario: Updated file content matches the compiled document
  Given the agent has overwritten the existing scope file
  When  the Developer reads the file
  Then  the file content is identical to the newly compiled scope document
  And   no residue from the previous version remains
```
