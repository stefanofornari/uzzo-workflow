## distribution/US-000014 — Publish the Uzzo Knowledge Base Content as a Lean Artifact

### User Story

```
AS A Developer
I WANT the canonical Uzzo knowledge base content (skills, standards, seed articles) published as a lightweight artifact
SO THAT tools such as the NetBeans plugin can initialize a knowledge base programmatically without pulling in the agent dependencies
```

#### Status
DONE

#### Dependencies
- None

#### Technical Context & Constraints
* **Target System**: Maven build of `uzzo-workflow`, consumed by other Maven projects (e.g. `nb-uzzo-workflow`).
* **Toolchain / Rules**: Java 21, Maven, JUnit 5, AssertJ; coding standard `uzz/project/coding_standard.md`.

#### Notes
1. `src/main/uzz/` stays the single source of truth and keeps its location (the `uzzo-init` skill and the README reference it).
2. A new module `uzzo-workflow-kb` (artifact `com.github.stefanofornari:uzzo-workflow-kb`, no compile or runtime dependencies) maps `src/main/uzz/**` to the `uzz/` prefix of the classpath. The repository becomes a multi-module build: parent `uzzo-workflow-parent` with modules `uzzo-workflow-kb` and `uzzo-workflow` (the agent code, artifact id unchanged).
3. `.DS_Store` files are excluded from the artifact.
4. No index file is generated: consumers locate the content from a known resource (e.g. `/uzz/skills/kb/SKILL.md`) and list it through the location it resolves to (jar or directory).
5. Because the artifact has its own pom, consumers need no dependency exclusions.
6. Files not shipped as files today (`project/overview.md`, `stories/index.md`) are not added; consumers generate them from `skills/uzzo-init/references/templates.md`.

### Acceptance Criteria

```gherkin
Scenario: Content available on the classpath
  Given the project is built
  Then  "uzz/skills/kb/SKILL.md" and "uzz/skills/kb/references/user_story.md" are readable as classpath resources

Scenario: OS and editor files are not shipped
  Given a ".DS_Store" file exists under "src/main/uzz"
  When  the project is built
  Then  it is not copied to the classpath resources

Scenario: Lean kb artifact
  Given the project is built
  Then  the "uzzo-workflow-kb" artifact contains only "uzz/**" entries and the META-INF metadata
  And   it contains no ".class" file
  And   it declares no compile or runtime dependency
```
