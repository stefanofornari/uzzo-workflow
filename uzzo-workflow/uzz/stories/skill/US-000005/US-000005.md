## skill/US-000005 — Fail Clearly When a Skill Is Missing or Unreadable

### User Story

```
AS A Developer
I WANT a clear error when the skill resource of an agent cannot be found or read
SO THAT I can fix a packaging or classpath problem quickly instead of debugging an agent that behaves oddly
```

#### Status
WIP

#### Dependencies
- skill/US-000004

#### Technical Context & Constraints
* **Target System**: Any JVM host application that embeds the Uzzo Workflow library (e.g. ViberFX, ViberCLI)
* **Toolchain / Rules**: Java 21, Maven, LangChain4j 1.21.0; coding standard `uzz/project/coding_standard.md`; development framework `uzz/project/development_framework.md`

#### Notes
1. Implemented in `AgentSystemMessage.loadSkill`; no test covers it yet, hence the WIP status.
2. Because the builders resolve the skill through a `systemMessageProvider`, the error shows up when the agent is invoked, not when it is built.
3. A missing resource raises `IllegalStateException`; an I/O failure while reading raises `UncheckedIOException`.

### Acceptance Criteria

```gherkin
Scenario: Skill resource is missing
  Given a skill resource path that is not on the classpath
  When  the Developer loads it with AgentSystemMessage.loadSkill
  Then  an IllegalStateException is thrown
  And   its message is "Missing system prompt resource: <path>"

Scenario: Skill resource cannot be read
  Given a skill resource that exists but fails while being read
  When  the Developer loads it with AgentSystemMessage.loadSkill
  Then  an UncheckedIOException is thrown
  And   its message is "Unable to read system prompt resource: <path>"
```
