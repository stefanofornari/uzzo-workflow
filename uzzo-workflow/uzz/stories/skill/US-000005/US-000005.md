## skill/US-000005 — Fail Clearly When a Skill Is Missing or Unreadable

### User Story

```
AS A Developer
I WANT a clear error when the skill resource of an agent cannot be found or read
SO THAT I can fix a packaging or classpath problem quickly instead of debugging an agent that behaves oddly
```

#### Status
DONE

#### Dependencies
- skill/US-000004

#### Notes
1. Target system: Any JVM host application that embeds the Uzzo Workflow library (e.g. ViberFX, ViberCLI). Toolchain and rules: Java 21, Maven, LangChain4j 1.21.0; coding standard `uzz/project/coding_standard.md`; development framework `uzz/project/development_framework.md`.
2. Implemented in `AgentSystemMessage.loadSkill`. `AgentSystemMessageTest` covers both scenarios: the unreadable stream is simulated by overriding `resolve(String)`, the extension point through which hosts can also change where skills are loaded from.
3. Because the builders resolve the skill through a `systemMessageProvider`, the error shows up when the agent is invoked, not when it is built.
4. A missing resource raises `IllegalStateException`; an I/O failure while reading raises `UncheckedIOException`.

### Acceptance Criteria

```gherkin
Scenario: Skill resource is missing
  Given a skill resource path that is not on the classpath
  When  the Developer loads it with AgentSystemMessage.loadSkill
  Then  an IllegalStateException is thrown
  And   its message is "Missing system prompt resource: <path>"

Scenario: Skill resource cannot be read
  Given a skill resource that exists but fails while being read
  When  the Developer loads it with AgentSystemMessage.loadSkill
  Then  an UncheckedIOException is thrown
  And   its message is "Unable to read system prompt resource: <path>"
```
