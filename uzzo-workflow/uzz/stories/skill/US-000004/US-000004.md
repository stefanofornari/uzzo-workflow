## skill/US-000004 — Use a Skill as the Agent System Prompt

### User Story

```
AS A Developer
I WANT the agent's system prompt to be taken from a skill file of the knowledge base found on the classpath
SO THAT agent behaviour is defined by editable skill documents instead of prompt strings hard-coded in my application
```

#### Status
DONE

#### Dependencies
- None

#### Notes
1. Target system: Any JVM host application that embeds the Uzzo Workflow library (e.g. ViberFX, ViberCLI). Toolchain and rules: Java 21, Maven, LangChain4j 1.21.0; coding standard `uzz/project/coding_standard.md`; development framework `uzz/project/development_framework.md`.
2. `AgentSystemMessage.loadSkill(String)` reads the resource returned by the overridable `resolve(String)` (by default a classpath resource) as UTF-8 and returns its text without the leading YAML frontmatter block (`---` ... `---`).
3. The skills (`uzz/skills/<name>/SKILL.md`) are shipped by the `uzzo-workflow-kb` dependency.
4. Only the skill body reaches the model: metadata such as `name` and `description` is for tools and humans, not for the prompt.

### Acceptance Criteria

```gherkin
Scenario: Skill with frontmatter becomes the system prompt
  Given the classpath resource uzz/skills/scope/SKILL.md starts with a YAML frontmatter block
  When  the Developer builds an agent with that skill as system message and invokes it
  Then  the first message sent to the model is a SYSTEM message
  And   its text starts with the first heading of the skill body
  And   it does not contain the frontmatter keys

Scenario: Each action uses its own skill
  Given agents built with the scope, story and code skills
  When  each agent is invoked
  Then  the system message of each agent starts with the heading of its own skill
```
