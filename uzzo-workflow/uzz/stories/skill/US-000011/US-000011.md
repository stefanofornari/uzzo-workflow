## skill/US-000011 — Let Every Agent Activate the uzzo-kb Skill

### User Story

```
AS A Developer
I WANT the agents built by UzzoAgentBuilder to be able to activate the uzzo-kb skill on demand
SO THAT the model can read the Knowledge Base conventions when it needs them, without any extra wiring on my side
```

#### Technical Context & Constraints
* **Target System**: Any JVM host application that embeds the Uzzo Workflow library (e.g. ViberFX, ViberCLI)
* **Toolchain / Rules**: Java 21, Maven, LangChain4j 1.21.0 Skills in Tool Mode; `uzzo-workflow-kb` 0.0.1-SNAPSHOT; coding standard `uzz/project/coding_standard.md`; development framework `uzz/project/development_framework.md`

#### Notes
1. The skill is built from the classpath resource `uzz/skills/uzzo-kb/SKILL.md`, not from a directory, so it works from inside a jar; the existing skill loading and frontmatter handling are reused.
2. `UzzoAgentBuilder` sets the `Skills` tool provider (the `activate_skill` tool) on each `AiServices` and adds the skill catalogue to the system message, after the agent's own skill. The agent's own skill stays the system prompt.
3. Always on for the scope, story and code agents; no switch.
4. To verify before implementing: which LangChain4j artifact and version provide `dev.langchain4j.skill`, and how to define a skill programmatically from text.
5. The tools the host adds with `.tools(...)` must keep working next to the skill tools.

### Acceptance Criteria

```gherkin
Scenario Outline: The model is told the uzzo-kb skill is available
  Given the Developer calls <builder> of UzzoAgentBuilder
  When  the Developer adds a streaming chat model, builds the agent and invokes it
  Then  the system prompt still starts with the agent's own skill
  And   it lists the uzzo-kb skill in the catalogue of available skills
  And   the model is offered the activate_skill tool

  Examples:
    | builder             |
    | ScopeAgentBuilder() |
    | StoryAgentBuilder() |
    | CodeAgentBuilder()  |

Scenario: The model activates the uzzo-kb skill
  Given an agent built with UzzoAgentBuilder
  When  the model requests the tool activate_skill for uzzo-kb
  Then  the body of the uzzo-kb skill, without its frontmatter, is given back to the model

Scenario: The Developer's own tools keep working
  Given an agent built with UzzoAgentBuilder and the Developer's AskTools implementation
  When  the model requests the tool AskQuestion
  Then  the Developer's implementation is invoked as before

Scenario: The uzzo-kb skill is missing from the classpath
  Given a classpath without uzz/skills/uzzo-kb/SKILL.md
  When  the Developer builds the agent and invokes it
  Then  the invocation fails with an IllegalStateException about the missing system prompt resource
```
