## ask/US-000008 — Let the Agent Offer the User a Choice

### User Story

```
AS A Developer
I WANT to plug my own implementation of the AskSingleChoice and AskMultipleChoice tools into an agent
SO THAT the agent can let the user pick from a list of options instead of typing an answer
```

#### Status
DONE

#### Dependencies
- ask/US-000010

#### Technical Context & Constraints
* **Target System**: Any JVM host application that embeds the Uzzo Workflow library (e.g. ViberFX, ViberCLI)
* **Toolchain / Rules**: Java 21, Maven, LangChain4j 1.21.0; coding standard `uzz/project/coding_standard.md`; development framework `uzz/project/development_framework.md`

#### Notes
1. `askSingleChoice(question, options)` returns the selected option; `askMultipleChoice(question, options)` returns the list of selected options.
2. The tool names are `AskSingleChoice` and `AskMultipleChoice`.
3. Covered by `AskChoiceToolsTest`: single choice, multiple choice and the no-answer case for each (the story only lists single choice for no answer; multiple choice is tested too). Tests run and green.
4. The tests drive the tools with `DummyStreamingChatModel` and a JSON object after `with arguments:`, which needs xtest 3.14.1 or later (earlier versions could only pass a single `{"prompt": ...}` argument).

### Acceptance Criteria

```gherkin
Scenario: User selects one option
  Given an agent built with the Developer's AskTools implementation
  When  the model requests the tool AskSingleChoice with a question and a list of options
  Then  askSingleChoice of the Developer's implementation is invoked with them
  And   the selected option is given back to the model

Scenario: User selects several options
  Given an agent built with the Developer's AskTools implementation
  When  the model requests the tool AskMultipleChoice with a question and a list of options
  Then  askMultipleChoice of the Developer's implementation is invoked with them
  And   the list of selected options is given back to the model

Scenario: User has no answer
  Given an agent built with the Developer's AskTools implementation
  When  the Developer's askSingleChoice throws a NoAnswerException
  Then  the model is told "<NO ANSWER PROVIDED>"
```
